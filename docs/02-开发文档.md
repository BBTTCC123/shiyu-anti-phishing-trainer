## 1. 作品概述

**一句话定义**：《识渔计划》是一个运行在手机浏览器里的反钓鱼诈骗训练游戏——用户在仿真的邮件、短信、链接页面中反复练习识别钓鱼攻击，每一处误判都有 AI 逐条讲解，练完生成个人"受骗风险画像"。

**基本形态**：H5 网页（HTTPS 链接 + 二维码扫码进入），单局 10–15 分钟，免安装、免注册（匿名作答），适配手机竖屏与桌面浏览器。

**产品定位**：反诈宣传的"演练场"。现有反诈教育（讲座、海报、推文）是单向灌输，本作品提供的是可重复、可量化、有反馈的**行为训练**。

## 2. 产品背景

### 2.1 问题现状

电信网络诈骗是侵害高校学生权益的高发类型。参照国家反诈中心公开宣传的高发诈骗手法，针对学生群体的钓鱼攻击主要集中在：冒充奖助学金/补助发放、冒充电商或快递客服退款、刷单返利兼职、冒充导师或教务部门的邮件、虚假购票/游戏交易等。新生对校园类邮件缺乏辨识经验，入学季是受害高峰。

钓鱼攻击的共同特征是：**它看起来正常**。受害者不是不知道"有诈骗"，而是没能在具体的一封邮件、一条链接面前做出正确判断——这是一种需要训练的行为能力，不是听过就能具备的知识。

### 2.2 现有手段的不足

| 现有手段 | 缺陷 |
|---|---|
| 反诈讲座、海报、推文 | 单向灌输，无练习、无反馈，遗忘快 |
| 真实攻防演练 | 组织成本高、有真实风险，无法常态化 |
| 通用答题 H5 | 题目静态、判定只有对错两值、无讲解、无个体分析 |

### 2.3 技术时机

大语言模型使"按需生成可控、可复现、可审核的模拟钓鱼样本"在成本上首次可行；轻量自然语言分类模型可在普通服务器甚至浏览器端实现实时判分。这使得"人人可练、天天可练、练完有报告"的反诈训练平台具备了落地条件。本作品是上述两个技术条件在校园反诈场景下的完整工程实现。

## 4. 应用价值

**对个人**：把"听过反诈宣传"变成"识别率实测提升"。平台内置前后测机制（训练前 10 题、训练后 10 题），个人报告直接给出识别率变化与薄弱维度。

**对学校**：为新生安全教育提供可组织、可量化的演练工具。辅导员发起班级演练，学生扫码进入，平台输出匿名汇总报告（全班薄弱破绽类型分布），使安全教育从"办过讲座"变为"练出数据"。

**对学院与社会**：网络安全方向的科普实践成果，与学院承办省级网络安全赛事的方向一致；作品沉淀的"生成—审核—标注—评测"样本工程链，可复用于后续教学与竞赛。

## 5. 产品设计

### 5.1 核心训练循环

每一道题的完整闭环：

```
样本呈现(拟真界面) → 真假判断 → 圈选破绽(点选可疑元素) → 双维计分
   → AI逐条讲解(圈对/漏判/误报) → 能力值结算 → 下一题
```

与"二选一答题"的本质区别在于**圈选破绽**：用户必须定位到具体元素（发件人域名、链接、话术、附件），系统才知道用户是"蒙对的"还是"真会了"，讲解也能精确到每一处。

### 5.2 样本体系

三类载体 × 三档难度：

| 载体 | L1 入门 | L2 进阶 | L3 高难 |
|---|---|---|---|
| 邮件 | 错别字、异常发件箱 | 仿冒域名、子域伪装、紧迫话术 | 结合虚构人设的定向钓鱼，破绽仅在回复地址 |
| 短信 | 明显诈骗话术 | 短链、奖金钱财钩子 | 正常通知中夹带一处链接异常 |
| 链接页 | 粗糙仿冒登录页 | 高仿页面+域名细节差异 | 页面完全正常，异常在跳转逻辑 |

破绽体系（判定与讲解的依据）共 7 类：域名仿冒、紧迫话术、冒充权威、链接不符、利诱钩子、附件风险、索要个人信息。

### 5.3 进阶模式：造浪者攻防

训练模式通关后解锁。用户切换到攻击者视角：从"基因卡"（拟态皮肤 × 心理机制 × 技术手段，共 8 张）中拖拽组合，构造一封模拟钓鱼邮件，投放给平台内置的 AI 防线（判分模型）。系统回合制反馈检出率与被识破的破绽，用户迭代改造对抗防线，最多 3 回合。

对抗结束自动复盘：用户使用过的每张基因卡对应一条防御知识——**从攻击者视角完成防守学习**。该模式为纯产品内模拟，无任何对外发送能力。

### 5.4 元系统

五维能力值（域名甄别 / 话术免疫 / 链接警惕 / 附件谨慎 / 紧迫感抗压）→ 段位（青铜识路人→王者防线）→ 结业报告（能力雷达图 + 薄弱项 + 个性化建议 + 全平台常错破绽 TOP3）。

### 5.5 视觉与交互设计

整体风格：深色底 + 警戒红/安全青双色的科技风界面；样本呈现采用高保真拟真客户端（邮件/短信/浏览器），所有样本界面带"教学模拟"水印。核心交互演出为**扫描拆解动效**：判定后样本界面以层叠方式展开（发件人层/内容层/链接层），圈选命中的破绽弹出全息标签，漏判项以红色脉冲提示——把"讲解"做成可观看的演出。开场与结算配数据粒子动效与音效。

## 6. 创新点

1. **攻防双视角训练法**：不仅"识别钓鱼"，还让用户在规则沙箱内"构造钓鱼"对抗 AI 防线，从攻击者视角建立防御直觉。攻防转换的教育设计在同类反诈产品中少见。
2. **圈选式微观判定**：把判定粒度从"这封是不是钓鱼"细化到"这个元素是不是破绽"，支撑精确讲解与细粒度能力画像。
3. **可控可复现的样本生成管线**：LLM 按人工编排的场景策略库与结构化 Schema 生成样本，随机种子与模板版本入库存档，全部样本经人工审核后入库——生成内容"可用、可查、可复现"。
4. **自训判分模型**：判分引擎为规则层 + 在自建数据集上训练的轻量文本分类模型，公开准确率/召回率/F1 与混淆矩阵；区别于直接调用通用大模型接口的同类做法。
5. **个体风险画像**：基于作答行为输出五维雷达与个性化建议，使训练结果可量化、可跟踪。
6. **合规内建**：全虚构样本、链接禁真实跳转、零个人信息采集、教学模拟水印——安全护栏作为产品设计而非事后补丁。
7. **双向判定 · 清白之证**：不止测「有没有抓到钓鱼」，也为正常样本出具「清白之证」（逐条说明为什么可信）并统计误报——把「不冤枉正常」纳入能力画像，补上同类产品普遍缺失的误报防治维度。

## 7. 系统架构与关键技术

```
┌─────────────── H5 前端（Vue 3，移动优先） ───────────────┐
│ 拟真客户端组件 │ 圈选交互 │ 拆解动效 │ 能力雷达 │ 匿名会话 │
└────────────────────────┬───────────────────────────────┘
                         │ HTTPS API
┌────────────────────────┴───────────────────────────────┐
│ 后端（FastAPI + SQLite）                                  │
│ 题库服务 │ 作答记录 │ 计分服务 │ 匿名汇总统计              │
│  ┌────────────┐   ┌──────────────────────────────────┐  │
│  │ 规则引擎    │   │ 文本分类模型（自建数据集训练→ONNX）│  │
│  └────────────┘   └──────────────────────────────────┘  │
│  LLM 生成管线（训练期离线运行）：策略库 → 提示词模板 →      │
│  Schema 约束输出 → 人工审核 → 入库（种子/版本存档）         │
└─────────────────────────────────────────────────────────┘
```

关键设计说明：

- **生成管线在训练期离线运行**，比赛运行期只读题库——判分与讲解不依赖外部大模型接口的实时可用性，保证演示稳定；"每日挑战"动态生成作为演示项保留。
- **两层判分**：规则层覆盖确定性特征（域名白名单/同形字符、URL 结构、话术词表），模型层覆盖语义特征；模型输出在服务端推理，浏览器端 ONNX 推理作为备选演示点。
- **讲解生成**：讲解文本由模板 + 标注字段渲染，仅"个性化建议"段落调用 LLM 流式生成——把外部依赖压缩到最小。

## 8. 数据与题库方案

| 库 | 规模 | 来源 | 用途 |
|---|---|---|---|
| 精标库 | 80 题 | LLM 初稿 + 双人人工审核标注 | 训练模式主线、前后测 |
| 生成库 | 200+ 题 | 生成管线自动产出，抽检 | 每日挑战、模型训练扩充 |
| 评测集 | 40 题 | 精标库划分，不参与训练 | 模型评测（P/R/F1、混淆矩阵） |

标注规范：每题按破绽 Schema 标注类别与文本片段，双人独立标注，一致性（Kappa 系数）写入作品文档；分歧样本仲裁后入库。

---

## 9. 评测与验证方案

1. **模型评测**：在评测集上报告总体与分类别（7 类破绽）的准确率、精确率、召回率、F1 及混淆矩阵。
2. **用户前后测**：招募 20–30 名在校生，训练前测 10 题 → 完成训练模式 → 后测 10 题（同难度不同题），报告平均识别率变化与分维度提升；样本量与测试条件如实写明。
3. **可用性观察**：记录首用时无需说明即可完成首关的比率、平均单题用时、圈选交互误操作率。

---

## 10. 合规与安全设计

- **教学模拟定位**：产品仅为识别训练模拟器，界面全程带"教学模拟"水印，不提供任何消息发送、转发功能；
- **全虚构原则**：发件人、机构、域名均为虚构（演示用保留域），所有链接仅指向产品内本地演示页，从生成源头禁止真实可跳转地址与真实个人信息；
- **内容审核**：生成样本入库前 100% 人工审核，剔除涉真实机构、真实联系方式或不当内容；
- **隐私保护**：免登录、匿名会话，不采集任何个人身份信息，作答数据仅用于汇总统计；
- **AI 生成内容标识**：按竞赛要求提交《AI 工具使用说明》，说明生成式 AI 在样本生成、代码辅助等环节的使用范围、人工审核流程与合规措施。

## 11. 开发实施方案

### 11.1 技术选型

| 模块 | 选型 |
|---|---|
| 前端 | Vue 3 + Vite；ECharts（雷达/统计）；GSAP + CSS 3D（拆解动效） |
| 后端 | Python FastAPI + SQLite；Uvicorn |
| 判分模型 | scikit-learn（TF-IDF + 线性模型）起步，视效果升级小型中文 BERT；导出 ONNX |
| 生成管线 | 国产大模型 API（DeepSeek/通义/讯飞星辰等任一），JSON Schema 约束输出 |
| 部署 | 校内服务器或云主机，HTTPS + 二维码入口 |

### 11.4 风险与降级预案

| 风险 | 预案 |
|---|---|
| 生成样本质量不稳定 | 提示词迭代 + 少样本示例；仍不达标的类别转纯人工编写 |
